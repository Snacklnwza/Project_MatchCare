# ฐานข้อมูล MatchCare

แอปเชื่อม Supabase PostgreSQL จริงผ่าน Supabase Auth, Data API, Storage และ RPC ไฟล์ SQL ในโฟลเดอร์นี้เป็น source สำหรับสร้างฐานใหม่ ตรวจทาน และทดสอบ ไม่ใช่ฐานข้อมูลที่แอปอ่านอยู่โดยตรง

## หน้าที่ของแต่ละโฟลเดอร์

- `schema/` — SQL ฉบับเต็มสำหรับสร้างฐานใหม่ เรียงไฟล์ `01` ถึง `20` ตามลำดับ แต่ละไฟล์เพิ่มระบบต่อจากไฟล์ก่อนหน้า
- `tests/` — SQL ตรวจสิทธิ์และพฤติกรรม รวม `run-local.mjs` ที่สร้าง PGlite ชั่วคราว
- `archive/migrations/` — patch เก่าสำหรับอ้างอิง
- `../supabase/migrations/` — ประวัติ migration รุ่นแรก ๆ ที่เคยติดตั้งผ่าน Supabase CLI

## การติดตั้งและอัปเดต

สำหรับ **ฐานใหม่ที่ว่าง** ให้เปิด SQL ใน `schema/` ตามลำดับชื่อไฟล์และรันแต่ละไฟล์ทั้งไฟล์ใน Supabase SQL Editor หลังตั้งค่า Auth และ Storage ตามที่ระบบต้องใช้

สำหรับ **ฐานเดิมที่มีข้อมูล** ห้ามรันชุด `schema/` ซ้ำ ตรวจโครงสร้างและประวัติบน Supabase ก่อน แล้วใช้เฉพาะ SQL ส่วนที่ยังขาด โครงการนี้เคยติดตั้งบางส่วนผ่าน migration และส่วนหลังผ่าน SQL Editor ตามข้อตกลงวันที่ 10 ตุลาคม 2569 จึงไม่ควรสรุปว่าการมีไฟล์ใน Git หมายถึงฐานจริงติดตั้งตรงกันทุกส่วน

การเปลี่ยนฐานในอนาคตควรเก็บ SQL ที่รันจริงพร้อมวันที่และผลตรวจไว้ให้ย้อนตรวจได้ การแก้ไฟล์ SQL ในเครื่องอย่างเดียวจะไม่เปลี่ยนฐาน Supabase

## ทดสอบ

จากโฟลเดอร์ `database` รัน `npm ci` และ `npm test`

คำสั่งนี้รัน schema และชุด regression บน PGlite ในเครื่อง **ไม่เชื่อม Supabase จริง** หากต้องยืนยันการส่งงาน ให้ทดสอบสิทธิ์และ flow หลักกับบัญชีทดสอบบน Supabase/Vercel โดยแยกข้อมูลสมมติจากข้อมูลจริง

ฟังก์ชันภายในฐานอยู่ใน schema `match_internal` ซึ่งไม่ควรเปิดผ่าน Data API; RPC ที่แอปเรียกอยู่ใน `public` และต้องตรวจสิทธิ์ผู้เรียกตามบทบาทและเจ้าของข้อมูล
