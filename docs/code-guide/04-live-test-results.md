## ข้อมูลสมมติที่เก็บไว้ให้ตรวจหน้าจอ

- ใช้บัญชีเดิม `employer.test@example.com`, `caregiver.test@example.com`, `admin.test@example.com` ไม่มีการเปลี่ยนรหัสผ่านหรือบทบาท
- สร้างโปรไฟล์ให้บัญชี caregiver ทดสอบที่เดิมยังไม่มี พร้อมทักษะสองรายการ
- เอกสารชื่อ `TEST-ONLY-ข้อมูลสมมติ.png` เป็นภาพเล็กสำหรับทดสอบ ไม่ใช่เอกสารบุคคลจริง แอดมินทดสอบอนุมัติแล้ว
- ผู้ป่วยชื่อ “ทดสอบระบบ ข้อมูลสมมติ”
- ประกาศชื่อ `[TEST] ทดสอบจับคู่ 28-09-2026` จับคู่แล้ว ใช้ตรวจหน้าคำเชิญและข้อมูลติดต่อได้
- เก็บไฟล์ไว้ใน private bucket โดยไม่เพิ่มสิทธิ์ลบหรือเขียนทับไฟล์ที่อนุมัติแล้ว
- ไม่เก็บรหัสผ่านหรือ session token ในคู่มือหรือโค้ดที่ส่งเข้า Git

## ขอบเขตที่ยังไม่ยืนยัน

ผู้ใช้ยืนยันในแชทว่าทดสอบผ่านหน้าเว็บครบทั้ง 5 ขั้นแล้ว ตั้งแต่บันทึกโปรไฟล์และส่งเอกสาร ไปจนทั้งสองฝ่ายเปิดข้อมูลติดต่อหลังจับคู่ โดยไม่ได้ระบุว่าเป็น localhost หรือ Vercel ผลนี้เป็นการทดสอบด้วยมือของผู้ใช้ แยกจากผลทดสอบอัตโนมัติข้างต้น

ยังไม่ทดสอบการแข่งขันตอบรับจากสอง connection พร้อมกัน, ความล้มเหลวของเครือข่ายระหว่าง upload กับ RPC, และ flow ทั้งหมดบน Vercel หลัง deploy รอบนี้ ไม่มีการอ้างว่าผล SQL หรือ UI mock แทนผลเหล่านี้

Security advisors หลังติดตั้งเหลือคำเตือนเดิมเรื่อง Auth leaked password protection ไม่พบคำเตือน RLS ของตารางเอกสารแล้ว

## ตำแหน่งไฟล์

- `database/schema/` — SQL รวมตามระบบ สำหรับสร้างฐานใหม่
- `supabase/migrations/` — การเปลี่ยนแปลงฐานเดิม ใช้ version ตรงกับประวัติจริง
- `database/tests/` — SQL regression และตัวรันฐานชั่วคราวในเครื่อง
- `frontend/src/pages/` — หน้าจอ
- `frontend/src/components/` — ส่วนประกอบใช้ซ้ำ
- `frontend/src/styles/` — CSS
- `frontend/src/lib/` — การเรียก API และข้อความร่วม
- `frontend/src/hooks/` — พฤติกรรม React ที่ใช้ซ้ำ
- `docs/code-guide/` — คู่มือและผลทดสอบ
- `output/` — หลักฐาน/script เฉพาะรอบทดสอบ ไม่ deploy และไม่ commit
