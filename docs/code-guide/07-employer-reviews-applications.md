# ผู้ว่าจ้างพิจารณาใบสมัคร (ID 11)

เมื่อผู้ดูแลส่งใบสมัครแล้ว ผู้ว่าจ้างเปิดเมนู **ใบสมัครที่ได้รับ** เพื่อดูผู้สมัครของประกาศตนเอง พร้อมคำแนะนำตัว ประสบการณ์ และทักษะ ผู้ว่าจ้างรับหรือปฏิเสธได้เฉพาะใบสมัครที่ยังรอคำตอบและประกาศยังเปิดรับ

## โค้ดอยู่ตรงไหน

- `database/schema/08_invitations.sql` มี `list_received_applications()` สำหรับคืนเฉพาะใบสมัครของเจ้าของประกาศ ข้อมูลที่ส่งออกก่อนจับคู่ไม่มีโทรศัพท์ LINE เอกสาร และที่อยู่ละเอียด
- `respond_to_application()` ตรวจสิทธิ์ผู้ว่าจ้าง ล็อกประกาศก่อนล็อกใบสมัคร แล้วบันทึกการตัดสินใจ ถ้ารับผู้สมัคร จะเปลี่ยนประกาศเป็น `matched` และปิดคำขออื่นของประกาศใน transaction เดียวกัน
- ข้อบังคับ `match_requests_one_accepted` ที่มีอยู่เดิมช่วยกันไม่ให้ประกาศหนึ่งมีผู้ถูกตอบรับสองคน
- `frontend/src/pages/EmployerApplications.jsx` แสดงรายการ สถานะ ปุ่มรับ/ปฏิเสธ และข้อมูลติดต่อหลังจับคู่; `Applications.jsx` ให้ผู้ดูแลเห็นผล เปิดข้อมูลติดต่อ และแจ้งจบงานเมื่อเริ่มงานแล้ว
- `frontend/src/components/MatchContact.jsx` เป็นส่วนแสดงข้อมูลติดต่อที่ใช้ร่วมกับหน้าคำเชิญและใบสมัคร
- `database/tests/job_review_test.sql` ตรวจสิทธิ์ต่างบทบาท การปฏิเสธ การรับหนึ่งคน การปิดคำขออื่น และการเปิดข้อมูลติดต่อเฉพาะคู่ที่จับสำเร็จ

## ผลทดสอบ 1 ตุลาคม 2569

`npm --prefix database test`, lint และ production build ผ่าน ติดตั้ง RPC ใน Supabase ด้วย migration `employer_reviews_job_applications` แล้ว และทดสอบ SQL ที่ rollback ข้อมูลสมมติบนฐานจริงผ่าน ผู้ใช้ `authenticated` เรียก public RPC ได้ ส่วน `anon` เรียกไม่ได้

งานอยู่ใน [Draft PR #17](https://github.com/Snacklnwza/Project_MatchCare/pull/17) และ Vercel รายงานว่า Preview พร้อมแล้ว แต่ Preview ต้องผ่าน Vercel SSO และตัวควบคุม Chrome ถูกส่วนขยายอื่นบัง จึงยังต้องทดสอบหน้าจอแบบสองบัญชีบน Vercel และการตอบรับพร้อมกันจากคนละ connection ก่อนถือว่า Definition of Done ของ ID 11 ครบ
