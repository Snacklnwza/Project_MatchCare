# ค้นหาและคัดกรองผู้ดูแล (ID 9)

ผู้ว่าจ้างเปิดเมนู **ค้นหาผู้ดูแล** เพื่อดูคนที่ยืนยันตัวตนแล้วและพร้อมรับงาน กรองด้วยทักษะ จังหวัด อำเภอ และช่วงประสบการณ์ จากนั้นเปิดรายละเอียดสาธารณะได้ หากต้องการส่งคำเชิญ ให้ไปเลือกประกาศงานของตัวเองก่อน

## โค้ดอยู่ที่ไหน

| ส่วน | หน้าที่ |
| --- | --- |
| `database/schema/10_caregiver_search.sql` | ค้นและแบ่งหน้าที่ฐานข้อมูล ตรวจว่าผู้เรียกเป็นผู้ว่าจ้าง และคืนเฉพาะข้อมูลสาธารณะ |
| `supabase/migrations/20261002073712_caregiver_search_filters.sql` | เพิ่ม RPC ค้นหาบนฐานจริง |

| `frontend/src/lib/caregivers.js` | ส่งตัวกรองจากหน้าเว็บให้ RPC และขอครั้งละ 21 คนเพื่อรู้ว่ามีหน้าถัดไปหรือไม่ |
| `frontend/src/pages/CaregiverSearch.jsx` | ฟอร์มตัวกรอง รายการ รายละเอียด หน้าว่าง ข้อผิดพลาด และการแบ่งหน้า |

| `frontend/src/pages/RoleDashboard.jsx` | เชื่อมเมนูค้นหาผู้ดูแลเข้ากับหน้านี้ |

## ทำไมต้องค้นที่ฐานข้อมูล

ฟังก์ชัน `public.search_caregivers` เรียกฟังก์ชันภายใน `match_internal.search_caregivers` ชั้นในตรวจบทบาทผู้ว่าจ้าง แล้วกรอง `verification_status = 'verified'` และ `availability_status = 'available'` **ก่อน** แบ่งหน้า จึงไม่ต้องส่งโปรไฟล์ผู้ดูแลทั้งหมดมาให้เว็บคัดเอง กรณีส่งรหัสประกาศ ฟังก์ชันตรวจด้วยว่าเป็นประกาศที่ยังเปิดอยู่ของผู้ว่าจ้างคนนี้

ผลลัพธ์ระบุคอลัมน์ทีละตัว: ชื่อ พื้นที่ระดับจังหวัด/อำเภอ ประสบการณ์ และชื่อทักษะ พร้อมจำนวนทักษะตรงกับประกาศ (เมื่อระบุประกาศ) ฟังก์ชันไม่คืนเบอร์โทร อีเมล LINE ที่อยู่ละเอียด หรือเอกสาร คำแนะนำตัวเป็นข้อความอิสระที่อาจใส่ช่องทางติดต่อ จึงส่ง `bio` เป็น `null` ในผลค้นหา การเปิดเผยข้อมูลติดต่อยังใช้เส้นทางหลังจับคู่เดิม

หน้าเว็บแยกค่าที่กำลังกรอกกับค่าที่ใช้ค้นจริง กด **ค้นหาผู้ดูแล** จึงส่งค่าใหม่; กด **ล้างตัวกรอง** จะกลับไปดูทั้งหมด ผู้ดูแลที่เปลี่ยนสถานะจะหายไปในการค้นหาครั้งถัดไป ตัวเลือกทักษะโหลดเฉพาะรายการที่ยังเปิดใช้งาน ส่วนแท็กเก่าที่ผู้ดูแลเคยบันทึกยังแสดงชื่อในผลลัพธ์เพื่อรักษาประวัติ

## วิธีตรวจซ้ำ

1. ในเครื่องรัน `npm --prefix database test` จากโฟลเดอร์โปรเจกต์ ชุด `caregiver_search_test.sql` ใช้ข้อมูลสมมติและ `rollback` ทั้งชุด
2. ใน `frontend` รัน `npm run lint` และ `npm run build`
3. เข้าบัญชีผู้ว่าจ้าง เปิด **ค้นหาผู้ดูแล** ลองกรองทักษะ ประสบการณ์ จังหวัด/อำเภอ แล้วล้างตัวกรอง
4. เปิดรายละเอียด ตรวจว่ามีข้อมูลสาธารณะและไม่มีเบอร์/ที่อยู่ละเอียด ลองผลว่างและปุ่มลองอีกครั้งเมื่อ API ล้มเหลว
5. เปลี่ยนผู้ดูแลเป็นไม่พร้อมรับงาน แล้วค้นใหม่ ต้องไม่ปรากฏ; กลับมาพร้อมและ verified จึงปรากฏอีก

## ผลทดสอบ 2 ตุลาคม 2569

- SQL ในเครื่องผ่านทุก schema/test; SQL เดียวกันบน Supabase จริงผ่านโดย rollback รวมกรณีสิทธิ์ผิดบทบาท ตัวกรอง สถานะที่เปลี่ยน และคำแนะนำตัวที่ใส่เบอร์โทร
- Browser ใช้ component จริงกับ API สมมติ 2 คน ผ่านตัวกรองพื้นที่/ทักษะ ล้างตัวกรอง รายละเอียด ผลว่าง โหลดผิดพลาด/ลองใหม่ และมือถือ 390px ไม่ล้นแนวนอน
- Lint และ production build ผ่าน; build มีคำเตือนขนาด bundle เดิม
- Security advisor ไม่พบคำเตือนใหม่จาก ID 9; คำเตือนเดิมคือ Auth ยังไม่เปิด [Leaked Password Protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)
