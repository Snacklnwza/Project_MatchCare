# ผลรีวิว PR งานจับคู่และค้นหา Sprint 2

รีวิว PR #17 (พิจารณาใบสมัคร) และ PR #18 (คลังแท็กและค้นหาผู้ดูแล) ก่อนส่งให้ทีมตรวจ โค้ดสอง PR นี้ต่อกัน โดย #18 ใช้สาขาของ #17 เป็นฐาน

## สิ่งที่พบและแก้

1. รายการใบสมัครเคยส่ง `bio` ของผู้ดูแลให้ผู้ว่าจ้างก่อนจับคู่ ข้อความนี้อาจมีเบอร์โทรหรือ LINE ฟังก์ชัน `match_internal.list_received_applications` จึงคืน `bio = null` และหน้าเว็บไม่แสดงช่องนี้แล้ว ข้อมูลติดต่อยังเปิดผ่าน `get_match_contact` หลังจับคู่เท่านั้น
2. ฟังก์ชันจัดการใบสมัครใน schema สำหรับฐานใหม่ยังไม่ครบใน migration สำหรับฐานเก่า เพิ่ม migration ที่สร้าง public API และกำหนดสิทธิ์เรียกให้ครบ จึงอัปเกรดจาก `main` ได้
3. `useRemoteList` เคยแสดงข้อมูล/error จากหน้าหรือตัวกรองเก่าระหว่างโหลดใหม่ เปลี่ยนให้ผลลัพธ์ผูกกับ loader และรอบโหลด จึงไม่แสดงผลตอบกลับที่ล่าช้าผิดหน้า
4. API คลังแท็กเคยรับชื่อที่มีแต่ Tab หรือขึ้นบรรทัดใหม่ ปรับการตัดช่องว่างก่อนตรวจค่าและเพิ่มกรณีนี้ใน SQL test
5. หน้าโปรไฟล์ผู้ดูแลเคยบันทึกโปรไฟล์และทักษะด้วยหลายคำขอ หากคำขอหลังล้มเหลว ข้อมูลจะเปลี่ยนเพียงบางส่วน เปลี่ยนเป็น `save_caregiver_profile_with_skills` ซึ่งทำใน transaction เดียว ใช้ `security invoker` และ RLS เดิม ตรวจตัวตนจาก `auth.uid()` และบทบาทจาก `profiles` ไม่รับ ID เจ้าของจากผู้เรียก

## จุดที่ตรวจด้านสิทธิ์และความถูกต้อง

- การรับใบสมัครล็อกประกาศและคำขอตามลำดับเดิม ตรวจเจ้าของประกาศ สถานะคำขอ ความพร้อมและการยืนยันของผู้ดูแลก่อนเปลี่ยนสถานะ มี partial unique index กันการรับมากกว่าหนึ่งคน
- คลังแท็กให้แก้ได้เฉพาะแอดมินจริงตาม `profiles.role` และปิดใช้งานแทนการลบ รายการที่ปิดยังคงอ้างอิงประวัติเดิมได้ แต่เพิ่มใหม่ไม่ได้
- ผลค้นหาผู้ดูแลจำกัดเฉพาะผู้ที่ยืนยันและพร้อมรับงาน กรองก่อนแบ่งหน้า ไม่ส่งเบอร์/ที่อยู่หรือ `bio` ที่อาจมีข้อมูลติดต่อ
- RPC โปรไฟล์ยอมรับเฉพาะผู้ดูแลที่ล็อกอิน ตรวจข้อมูลและทักษะ เซฟสำเร็จพร้อมกันหรือย้อนกลับทั้งหมด ไม่แก้ `verification_status`

## หลักฐานทดสอบ

- `npm --prefix database test` ผ่านทุกไฟล์ รวมกรณีข้อมูลส่วนตัวรั่ว ชื่อแท็กเป็นช่องว่าง และบันทึกโปรไฟล์ล้มเหลวครึ่งทาง
- `npm --prefix database test -- --upgrade-from=8ddbf47` ผ่าน ใช้ schema ใน `main` แล้วลง migration ใหม่ทั้งหมดตามลำดับ
- SQL regression สำหรับใบสมัคร คลังแท็ก และโปรไฟล์ผ่านบน Supabase จริงแบบ `begin ... rollback` จึงไม่ทิ้งข้อมูลทดสอบ
- ทดสอบ React loader ใน browser ผ่านการเปลี่ยนหน้า error ค้าง ผลตอบกลับช้า และ retry; `npm --prefix frontend run lint` กับ production build ผ่าน
- Security Advisor ไม่พบคำเตือนใหม่จาก schema; ยังมีคำเตือนเดิมว่า Auth ปิด [leaked password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)

## สิ่งที่ยังต้องตรวจรับ

ทดสอบ flow ผู้ว่าจ้างและผู้ดูแลสองบัญชีบน Vercel หลังรวมและ deploy แล้ว เทียบ UI กับ Figma และเช็ก Acceptance Criteria ด้วยตนเองก่อนปิด Sprint 2 การผ่าน SQL/browser ในเครื่องยังไม่ใช่หลักฐานว่าหน้าจอ production ทั้งหมดผ่าน
