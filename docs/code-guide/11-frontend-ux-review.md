# รีวิว UX/UI ของ MatchCare

อัปเดต 3 ตุลาคม 2569 — รอบนี้ปรับเฉพาะส่วนหน้าเว็บ การทำงานกับฐานข้อมูลและสิทธิ์เดิมไม่ได้เปลี่ยน

## หลักที่ใช้จัดหน้า

- ให้เมนูบนบอกเส้นทางหลักของแต่ละบทบาท ไม่แสดงทุกงานย่อยพร้อมกัน
- ให้แต่ละหน้าตอบได้ว่า “นี่คือหน้าอะไร”, “ตอนนี้มีข้อมูลหรือยัง” และ “ทำอะไรต่อ”
- ใช้ชื่อสถานะภาษาไทยและสีช่วยแยกสถานะ แต่ยังคงข้อความไว้ให้อ่านได้โดยไม่ต้องพึ่งสี
- เมื่อไม่มีข้อมูล ให้บอกเหตุผลตามบริบทและมีปุ่มพาไปขั้นตอนที่ทำต่อได้
- บนจอเล็กให้เมนูเปิดปิดได้ ส่วนตัวกรองที่ใช้น้อยให้กางเมื่อจำเป็น

## วิเคราะห์และการปรับแต่ละส่วน

| ส่วน | สิ่งที่พบ | สิ่งที่ปรับในรอบนี้ |
| --- | --- | --- |
| เมนูผู้ว่าจ้าง | รายการ 7 อันอยู่แถวเดียวกัน อ่านยากและกินพื้นที่ | เหลือทางหลัก 4 รายการ และรวม “ใบสมัครที่ได้รับ/คำเชิญที่ส่ง” ไว้ใต้ “คำขอ”; ซ่อน “ประวัติการจ้างงาน” ที่ยังไม่มีฟังก์ชัน |
| เมนูผู้ดูแล/แอดมิน | เมนูยาวบนจอเล็ก และแอดมินมีหน้าจัดการผู้ใช้ที่ยังไม่พร้อม | ใช้ปุ่มเปิดเมนูบนมือถือ; ซ่อนหน้าจัดการผู้ใช้; ย้ายโปรไฟล์และเอกสารไว้ในเมนูบัญชีตามเดิม |
| เมนูร่วม/ท้ายหน้า | กระดิ่งและข้อความท้ายหน้าดูเหมือนกดได้แต่ไม่มีการทำงาน | เอาสัญลักษณ์แจ้งเตือนและลิงก์หลอกออก; ทำเครื่องหมายบัญชีให้จำง่ายขึ้น |
| หน้าแรกก่อนเข้าสู่ระบบ | ข้อความเดิมอ้างว่าทุกคนผ่านการตรวจและมีรีวิว ซึ่งระบบยังทำไม่ครบ | เขียนข้อความให้ตรงกับขั้นตอนที่มีจริง และย่อหัวข้อให้อ่านได้บนมือถือ |
| เข้าสู่ระบบ/สมัครสมาชิก/ตั้งค่าโปรไฟล์ | ฟอร์มมีเส้นทางเฉพาะของตัวเองอยู่แล้ว | ตรวจหน้าล็อกอินทั้งจอใหญ่และมือถือ; รอบนี้คงลำดับฟอร์มและการตรวจข้อมูลเดิม |
| หน้าหลักผู้ว่าจ้าง | เห็นสองรายการทันทีแต่ไม่มีคำอธิบายว่าเป็นภาพรวม | เพิ่มชื่อหน้า คำอธิบาย และจำนวนผู้ป่วย/ประกาศ; รายการสองฝั่งยังเลื่อนภายในกรอบได้ |
| ผู้ป่วยของฉัน | ปุ่มเพิ่มเป็นการ์ดท้ายรายการ ทำให้หาได้ยากเมื่อรายการยาว | ย้ายปุ่มเพิ่มไว้ข้างหัวข้อ และให้ทางเริ่มต้นชัดเจนเมื่อยังไม่มีผู้ป่วย |
| ประกาศงาน | สถานะว่างไม่แยกกรณีไม่มีประกาศกับกรณีกรองแล้วไม่พบ | แยกข้อความตามกรณี และมีทางกลับไปดูทั้งหมด |
| ค้นหาผู้ดูแล | ผลลัพธ์และทางไปเชิญมีอยู่แล้ว | คงลำดับค้นหา → ดูรายละเอียด → ไปยังประกาศ; ปรับพื้นที่อ่านการ์ดให้สม่ำเสมอ |
| ใบสมัครที่ได้รับ/คำเชิญที่ส่ง | หน้าว่างบอกเพียงว่าไม่มีรายการ | เพิ่มปุ่มไปประกาศงาน และทำป้ายสถานะให้แยกด้วยข้อความและสี |
| หน้าหลักผู้ดูแล | ปุ่มหลักชี้ไปโปรไฟล์เสมอ แม้ทำโปรไฟล์แล้ว | เปลี่ยนปุ่มตามขั้นตอนที่ค้าง: โปรไฟล์ → เอกสาร → พร้อมรับงาน → ค้นหางาน; ถ้ารอตรวจให้ไปดูสถานะเอกสาร |
| โปรไฟล์ผู้ดูแล | ฟอร์มบนมือถือเสี่ยงล้นแนวนอน และคำแนะนำตัวไม่บอกขอบเขตข้อมูล | จัดกรอบฟอร์มให้พอดีจอ เพิ่มหัวข้อ/คำแนะนำให้เล่าประสบการณ์โดยไม่ใส่ข้อมูลติดต่อ |
| เอกสารผู้ดูแล | มีขั้นตอนเลือกและส่งไฟล์อยู่แล้ว | ไม่เปลี่ยนฟอร์ม; ใช้ทางลัดจากหน้าหลักและเมนูบัญชีให้หาเจอ |
| ค้นหางาน | ตัวกรองทุกช่องเปิดพร้อมกัน ทำให้ผลลัพธ์อยู่ลึก | แสดงจังหวัด อำเภอ ทักษะก่อน; วันและค่าตอบแทนอยู่ใน “ตัวกรองเพิ่มเติม” พร้อมจำนวนที่เลือก; เพิ่มปุ่มล้างเมื่อไม่พบผล |
| งานที่สมัคร/คำเชิญที่ได้รับ | หน้าว่างไม่พาไปหางาน | เพิ่มปุ่มค้นหางานและป้ายสถานะที่สแกนได้ |
| หน้าหลักแอดมิน | พื้นที่ค่อนข้างว่างและไม่มีจุดเริ่มงาน | เพิ่มการ์ดงานตรวจเอกสารและคลังกลาง พร้อมปุ่มตรงไปแต่ละหน้า |
| ตรวจเอกสาร/คลังกลาง | มีรายการและฟอร์มทำงานอยู่แล้ว | ปรับการ์ดและสถานะว่างให้กลมกลืนกับหน้าอื่น; ไม่เปลี่ยนกติกาการอนุมัติ |

## ระยะหน้าและหัวข้อจากภาพตรวจ 3 ตุลาคม

หน้าตามบทบาทวางเนื้อหาชิดขอบซ้ายของกรอบหลักเดียวกับหน้าหลัก และใช้ความกว้างที่มีได้เต็มพื้นที่ ไม่บีบให้อยู่กลางจอ ลบบรรทัดคำเล็กสีเขียวเหนือหัวข้อทุกหน้าเพื่อให้หัวข้อหลักเป็นจุดเริ่มอ่าน หัวข้อหลักใช้ประมาณ 32px บนจอใหญ่และ 28px บนมือถือ โดยมีคำอธิบายอยู่ใต้หัวข้อ ปุ่มเพิ่มผู้ป่วย/สร้างประกาศอยู่ด้านขวาบนจอใหญ่และลงบรรทัดใหม่บนมือถือ ระหว่างโหลดข้อมูล หน้าผู้ป่วยยังคงหัวข้อไว้เพื่อไม่ให้ตำแหน่งหน้ากระโดด

## จุดที่ยังควรตรวจบนระบบจริง

- ทดสอบด้วยบัญชีทั้งสามบทบาทบน Vercel โดยเฉพาะรายการที่มีข้อมูลจำนวนมากและสถานะทุกแบบ
- ตรวจด้วยคีย์บอร์ดและโปรแกรมอ่านหน้าจอบนเบราว์เซอร์เป้าหมายอีกครั้ง
- เส้นทางประวัติการจ้างงานและจัดการผู้ใช้ยังไม่ได้เปิด เพราะฟังก์ชันยังไม่พร้อม
