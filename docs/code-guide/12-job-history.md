# ประวัติงานของผู้ว่าจ้างและผู้ดูแล (ID 16)

เปิดเมนูชื่อบัญชีด้านขวา แล้วกด **ประวัติงาน** ทั้งสองฝ่ายเห็นงานที่จับคู่สำเร็จจากใบสมัครและคำเชิญในหน้าเดียว เลือกดูงานทั้งหมด กำลังดำเนินงาน เสร็จสิ้น หรือยกเลิกได้ รายการใหม่อยู่ก่อนและแบ่งหน้าละ 20 งาน

## โค้ดแต่ละส่วนทำอะไร

- `pages/JobHistory.jsx` แสดงตัวกรอง การ์ดสถานะ คู่สัญญา พื้นที่ เวลา และค่าตอบแทน กดดูรายละเอียดเพื่อโหลดการดูแล ทักษะ และเวลาที่เริ่ม/จบงาน
- `lib/history.js` ส่งตัวกรองและตำแหน่งหน้าไปที่ RPC ขอครั้งละ 21 แถวเพื่อรู้ว่ามีหน้าถัดไป โดยแสดง 20 แถว
- `styles/JobHistory.css` จัดชื่อช่องกับค่าให้ตรงกัน บนมือถือเปลี่ยนเป็นเรียงลงเพื่อไม่บีบข้อความ
- `components/Navbar.jsx` เพิ่มทางเข้าในเมนูบัญชี และ `pages/RoleDashboard.jsx` เลือกแสดงหน้านี้ตามบทบาท
- `database/schema/11_job_history.sql` เป็น SQL สำหรับฐานใหม่ ส่วนฐานเดิมใช้ migration `20261009135153_job_history.sql` ซึ่งติดตั้งบน Supabase แล้ว

## ข้อมูลและสิทธิ์

`list_job_history` อ่านเฉพาะคำขอที่เป็น `accepted` ของผู้เรียก ไม่รวมใบสมัคร/คำเชิญที่ยังไม่ได้ตกลงจ้าง การกรองและแบ่งหน้าทำในฐานข้อมูล ไม่ใช่โหลดทั้งตารางมาซ่อนในหน้าเว็บ

`get_job_history_details` ตรวจคู่สัญญาอีกครั้งก่อนคืนรายละเอียด ทั้งสอง RPC ไม่ส่งชื่อผู้ป่วย เบอร์ LINE หรือที่อยู่ละเอียด รายละเอียดส่วนนี้ไม่ใช้แทน API ข้อมูลติดต่อ ผู้ไม่ล็อกอิน แอดมิน และบัญชีที่ไม่เกี่ยวข้องไม่มีสิทธิ์เปิดประวัติของคู่อื่น

หน้าอ่านสถานะ `cancelled` ที่มีอยู่ได้ การทำคำสั่งยกเลิกงานเป็นอีก flow และไม่ได้เพิ่มใน ID 16 รอบนี้

## ผลทดสอบ

- `job_history_test.sql` ผ่านในเครื่องและ Supabase จริงแบบ rollback: ประวัติทั้งสองเส้นทาง จำนวน 23 งาน แบ่งหน้า กรองสถานะ ลำดับ รายละเอียด และสิทธิ์บัญชีอื่น/แอดมิน/ผู้ไม่ล็อกอิน
- ชุด SQL เดิมและ lint ผ่าน
- การทดสอบหน้าเว็บใช้ component จริงกับ API สมมติ ตรวจเมนูทั้งสองบทบาท ตัวกรอง การแบ่งหน้า รายละเอียด ผลว่าง ลองใหม่ และมือถือ 390px แยกจากผลทดสอบ API จริง
- พบ footer เดิมใช้ `100vw` ซึ่งรวมความกว้าง scrollbar จนล้นมือถือ เปลี่ยนเป็นความกว้างตามกรอบและระยะขอบของหน้า

## ตรวจซ้ำ

รัน `npm --prefix database test` และ `npm --prefix frontend run lint` จาก root โปรเจกต์ ส่วน build ใช้ `npm run build -- --configLoader native` ใน `frontend`

หลัง deploy เปิดด้วยผู้ว่าจ้างและผู้ดูแล ตรวจว่างานที่เคยจับคู่ปรากฏเหมือนกัน เลือกสถานะและเปิดรายละเอียด บัญชีที่ไม่ได้รับเลือกต้องไม่มีงานนั้นในประวัติ
