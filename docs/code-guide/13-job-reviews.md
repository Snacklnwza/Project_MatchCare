# ให้ดาวและรีวิวหลังจบงาน (ID 15)

ผู้ว่าจ้างเปิดเมนูบัญชี → ประวัติงาน → เลือกงานเสร็จสิ้น → ดูรายละเอียดงาน แล้วให้คะแนน 1–5 ดาวและเขียนข้อความได้ไม่เกิน 1,000 ตัวอักษร ข้อความไม่บังคับ หนึ่งงานเขียนได้ครั้งเดียว เมื่อบันทึกแล้วฟอร์มเปลี่ยนเป็นรีวิวที่บันทึกไว้ ผู้ดูแลเปิดอ่านได้จากประวัติงานตนเอง

## โค้ดแต่ละส่วน

- `components/JobReview.jsx` โหลดรีวิวของงาน แสดงแบบอ่านอย่างเดียวหรือฟอร์มตามบทบาท กันการกดบันทึกซ้ำ และเก็บข้อความไว้หากบันทึกล้มเหลว
- `components/CaregiverReviews.jsx` แสดงคะแนนเฉลี่ย จำนวนรีวิวทั้งหมด และข้อความล่าสุดสูงสุด 5 รายการ ใช้ร่วมในหน้าค้นหาผู้ดูแล รายการผู้ดูแลสำหรับประกาศ และโปรไฟล์ของผู้ดูแลเอง
- `lib/reviews.js` เรียก RPC และแปลข้อผิดพลาดเป็นภาษาไทย
- `styles/Reviews.css` แยกสีคะแนนกับปุ่มหลัก ใช้ radio ที่เลือกด้วยคีย์บอร์ดได้ และจัดตัวเลือกดาวให้ลงแถวใหม่บนมือถือ
- `database/schema/12_job_reviews.sql` สร้างตารางและ API สำหรับฐานใหม่ ส่วนฐานเดิมใช้ migration `20261009190540_job_reviews.sql` ซึ่งติดตั้งบน Supabase แล้ว

## บันทึกข้อมูลอย่างไร

`submit_job_review` รับเฉพาะรหัสงาน คะแนน และข้อความ ฐานข้อมูลหาผู้ว่าจ้างจาก `auth.uid()` และหาผู้ดูแลจากคู่ที่เป็น `accepted` เอง หน้าเว็บส่งรหัสผู้เขียนหรือเปลี่ยนผู้รับรีวิวไม่ได้

ฟังก์ชันตรวจว่าผู้เรียกเป็นผู้ว่าจ้างเจ้าของประกาศและงานเป็น `completed` ก่อนเขียน Unique ของ `job_post_id` ป้องกันหนึ่งงานมีหลายรีวิว แม้เรียก API ซ้ำ ไม่เปิดสิทธิ์ INSERT/UPDATE/DELETE ตรงให้ผู้ใช้

`get_job_review` ให้เฉพาะคู่สัญญาอ่านรีวิวของงาน ส่วน `get_caregiver_reviews` ให้ผู้ว่าจ้างอ่านได้เมื่อผู้ดูแลยัง verified และ available ผู้ดูแลอ่านคะแนนตนเองได้แม้ปิดรับงาน

ผลค้นหาไม่ส่งรหัสงาน ผู้เขียน ชื่อผู้ป่วย ที่อยู่ หรือข้อมูลติดต่อ ข้อความรีวิวเป็นสิ่งที่ผู้ใช้เลือกเผยแพร่ หน้าเว็บจึงบอกให้ไม่ใส่ข้อมูลส่วนตัว และ React แสดงข้อความเป็นตัวหนังสือ ไม่ตีความเป็น HTML ระบบไม่ได้ตรวจชื่อผู้ป่วยในข้อความอิสระโดยอัตโนมัติ

## ผลทดสอบ

- `job_rating_test.sql` ผ่านทั้งในเครื่องและ Supabase จริงแบบ rollback: คะแนน 1–5 ข้อความยาวเกินกำหนด บัญชีผิดบทบาท งานยังไม่จบ/ยกเลิก รีวิวซ้ำ สิทธิ์อ่าน ค่าเฉลี่ย และจำนวนรีวิว
- ทดสอบฐานใหม่และอัปเกรดจาก main ก่อนเพิ่มฟังก์ชันทั้งสองผ่าน ชุด SQL เดิม lint และ production build ผ่าน
- UI ใช้ component จริงกับ API สมมติ: ไม่เลือกดาว บันทึกล้มเหลวแต่ข้อความไม่หาย กดซ้ำ บันทึกแล้วเปิดอ่านใหม่ ผู้ดูแลไม่มีฟอร์มเขียน คะแนนรวม ข้อความ HTML เป็นตัวหนังสือ และมือถือ 390px
- Security Advisor ไม่พบคำเตือนใหม่จากประวัติ/รีวิว เหลือคำเตือน Auth เดิมเรื่อง [Leaked Password Protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)

## ตรวจหลัง deploy

ใช้ผู้ว่าจ้างรีวิวงานที่จบแล้ว จากนั้นเปิดบัญชีผู้ดูแลอ่านรีวิวเดียวกัน และให้ผู้ว่าจ้างอีกคนดูคะแนนในหน้าค้นหาผู้ดูแล งานที่ยังไม่จบไม่ควรมีฟอร์มรีวิว และการเรียก API เขียนซ้ำต้องถูกปฏิเสธ
