# บันทึกงาน 30 กันยายน 2569

## เป้าหมายวันนี้

ปิด ID 6 ให้ผู้ดูแลค้นหาและดูประกาศที่เปิดรับได้ แล้วเตรียมทางไป ID 10 การสมัครงาน

## งานที่ทำ

- จัดลำดับ backlog ใน Google Sheets โดยเพิ่มคอลัมน์ลำดับทำงานและสถานะ เพื่อให้เน้นเส้นทางค้นหา → สมัคร → ตอบรับก่อน
- ตรวจ RLS ของ `job_posts` พบว่าผู้ดูแลอ่านตารางประกาศตรง ๆ ไม่ได้ เพราะนโยบายเดิมให้เจ้าของอ่านเท่านั้น
- เริ่มด้วย `list_open_jobs()` ผ่าน Supabase SQL Editor และตรวจว่าผู้ที่เข้าสู่ระบบเรียกได้ ผู้ไม่เข้าสู่ระบบเรียกไม่ได้ ผู้ดูแลเห็นประกาศเปิดรับบน localhost
- สร้างหน้า `JobSearch.jsx` และเชื่อมเมนู **ค้นหางาน** ผู้ดูแล ทดลองตัวกรองจังหวัด วันที่ และค่าตอบแทนร่วมกัน
- เปลี่ยนเป็น RPC `search_open_jobs()` เพื่อกรองที่ฐานข้อมูลก่อนแบ่งหน้า เพิ่มตัวกรองอำเภอ/เขตและทักษะ ปุ่มล้างตัวกรอง และหน้ารายละเอียดที่ตรวจสถานะงานซ้ำ
- หลังเทียบ acceptance ใน backlog เพิ่มปุ่ม **ค้นหา** ให้ผู้ใช้กดยืนยันตัวกรองก่อนโหลดผล และเพิ่มค่าตอบแทนสูงสุดให้กรองเป็นช่วงได้
- จัดหน้าจอค้นหาให้แยกส่วนตัวกรองกับรายการงาน ใช้งานได้บนจอแคบ และไม่แสดงชื่อผู้ป่วย ที่อยู่ละเอียด หรือข้อมูลติดต่อในการ์ด
- เริ่ม ID 10 เพิ่มประเภท `application` ใน `match_requests` และ RPC สมัครงาน ตรวจบทบาท สถานะยืนยันตัวตน ความพร้อมรับงาน และสถานะประกาศที่ฐานข้อมูล
- ป้องกันใบสมัครซ้ำและแยกใบสมัครจากคำเชิญเดิม ปุ่มตอบรับคำเชิญจึงไม่ใช้กับใบสมัครของตัวเอง
- เพิ่มปุ่มสมัครในรายละเอียดประกาศ และหน้า **งานที่สมัคร** สำหรับติดตามสถานะ `pending` พร้อมข้อความกรณียังไม่ผ่านการยืนยันตัวตน
- เขียนคู่มือโค้ด `docs/code-guide/06-job-applications.md` เพื่อให้คนรับช่วงอ่านหน้าที่ของแต่ละไฟล์ได้

## ผลตรวจ

- ชุดทดสอบ SQL ในเครื่องผ่าน รวมบทบาทผู้ใช้ งานปิด ตัวกรอง รายละเอียด และข้อมูลส่วนตัว
- หน้าเว็บผ่าน lint และ production build ด้วย Vite `--configLoader native`
- บน localhost บัญชีผู้ดูแลเห็นประกาศเปิดรับและรายละเอียดได้; เลือกจังหวัดที่ไม่มีงานหรือวันที่นอกช่วงแล้วแสดงรายการว่าง; ค่าตอบแทนขั้นต่ำ 2 บาทไม่พบงานตัวอย่าง 1 บาท และ 1 บาทพบงาน; ปุ่มล้างตัวกรองพารายการกลับมา
- Supabase security advisors ไม่พบคำเตือนใหม่จากฟังก์ชันนี้ คำเตือนที่มีอยู่เดิมคือการป้องกันรหัสผ่านรั่วใน Auth ยังไม่เปิด
- ชุดทดสอบใบสมัครผ่าน ทั้งกรณียังไม่อนุมัติ สมัครสำเร็จ สมัครซ้ำ ประกาศปิด สิทธิ์อ่าน และการแยกคำเชิญ; lint และ production build ผ่าน
- ติดตั้ง RPC ใบสมัครใน Supabase จริงแล้ว และตรวจสิทธิ์: `authenticated` เรียกได้ แต่ `anon` เรียกไม่ได้

## สถานะและขั้นต่อไป

ID 6 และฐานของ ID 10 ผ่านการทดสอบในเครื่องกับฐาน Supabase จริงแล้ว ยังต้องทดสอบ UI สมัครงานบน Vercel หลังนำโค้ดขึ้น และเช็ก acceptance ตาม backlog ด้วยตนเอง จึงยังไม่ปิด DoD ทั้งหมด งานต่อไปคือหน้าผู้ว่าจ้างพิจารณาใบสมัครและขั้นตอบรับ เพื่อให้จับคู่จากใบสมัครได้
