# บันทึกงาน 2 ตุลาคม 2569

## งานที่เก็บต่อจากรอบก่อน

- ปรับรายการประกาศงานในหน้าแรกผู้ว่าจ้างให้เลื่อนภายในกรอบสูงสุด 534px เท่ากับฝั่งรายชื่อผู้ป่วย หัวข้ออยู่ด้านนอกกรอบ
- แก้ `frontend/src/pages/EmployerDashboard.jsx` เพิ่ม class เฉพาะรายการประกาศ พร้อมชื่อ region และการโฟกัสด้วยคีย์บอร์ด
- แก้ `frontend/src/styles/App.css` ใช้กฎจำกัดความสูงร่วมกับรายการผู้ป่วย และเพิ่มเส้นแสดง focus

## ผลตรวจ

- Lint และ production build ผ่าน มีคำเตือนขนาด bundle เดิม
- ใช้ component จริงและข้อมูล API สมมติ 5 ประกาศใน browser ตรวจบน desktop 1440px และมือถือ 390px
- กรอบประกาศสูง 534px และเลื่อนด้วยเมาส์ได้ โดยฝั่งผู้ป่วยและหน้า desktop ไม่เลื่อนตาม
- เลื่อนด้วยคีย์บอร์ดบนมือถือได้ ไม่มีหน้าล้นแนวนอน และปุ่มจัดการประกาศยังเรียก navigation ได้
- กรณีมีหนึ่งประกาศไม่มีการเลื่อนเกินจำเป็น และกรณีไม่มีประกาศยังแสดงข้อความเดิม
- ลบหน้า harness ชั่วคราวหลังตรวจแล้ว ภาพทดสอบเก็บใน `output/playwright/` ซึ่งไม่ขึ้น Git

## สถานะ Sprint 2

### ID 8 — คลังกลาง

- เพิ่มหน้าแอดมินจัดการทักษะและรอยโรค เพิ่ม/แก้ไข/ปิดใช้งาน/เปิดกลับ พร้อมค้นชื่อและกรองสถานะ
- เพิ่ม RLS และ validation ป้องกันบัญชีทั่วไปแก้คลัง ชื่อว่าง และชื่อซ้ำ
- ปรับฟอร์มเก็บแท็กเดิมที่ถูกปิดใช้งาน และ SQL บันทึกข้อมูลอื่นโดยไม่ทำประวัติหาย
- ทดสอบฐานข้อมูลทั้งในเครื่องและฐานจริงแบบ rollback, browser API สมมติ desktop/mobile, lint และ build ผ่าน
- คู่มือ: [คลังกลาง ID 8](../code-guide/08-admin-catalog.md)

### ID 9 — ค้นหาผู้ดูแล

- เพิ่ม RPC ค้นหาผู้ดูแลที่ยืนยันแล้วและพร้อมรับงาน กรองทักษะ ประสบการณ์ จังหวัด/อำเภอ และแบ่งหน้าก่อนส่งผลให้เว็บ
- ปิดการส่งคำแนะนำตัวใน API สาธารณะ เพราะข้อความอิสระอาจมีเบอร์ติดต่อ; เพิ่ม migration และทดสอบกรณีนี้บนฐานจริง
- เพิ่มหน้าค้นหาและรายละเอียดสาธารณะในเมนูผู้ว่าจ้าง พร้อมผลว่าง ข้อผิดพลาด ปุ่มลองใหม่ และหน้าจอมือถือ
- ทดสอบ SQL ในเครื่องและฐาน Supabase จริงแบบ rollback ผ่าน รวมผู้ดูแลหลายสถานะ สิทธิ์ และข้อมูลส่วนตัว
- ทดสอบ component จริงด้วย API สมมติในเบราว์เซอร์ผ่าน desktop/mobile; lint และ build ผ่าน
- คู่มือ: [ค้นหาผู้ดูแล ID 9](../code-guide/09-caregiver-search.md)
