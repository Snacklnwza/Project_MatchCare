# บันทึกงาน 3 ตุลาคม 2569

## รีวิว PR ก่อนรวม Sprint 2

- ตรวจขอบเขต PR #17 และ #18: สิทธิ์ฐานข้อมูล ข้อมูลที่ API ส่งออก การตอบรับพร้อมกัน ประวัติแท็ก และสถานะโหลดข้อมูล
- พบ `list_received_applications` ส่ง `bio` ซึ่งอาจมีเบอร์/LINE ก่อนจับคู่ เพิ่ม regression test ให้ล้มก่อนแก้ แล้วเปลี่ยน API เป็น `null` และลบการแสดงช่องนี้ในรายการใบสมัคร
- พบ `useRemoteList` ไม่เริ่ม loading/ล้าง error เมื่อ loader เปลี่ยน แก้และทดสอบใน browser: เปลี่ยนหน้า ล้าง error เก่า ผลตอบกลับช้าไม่แทนที่หน้าปัจจุบัน และลองใหม่ ผ่าน
- เพิ่ม migration API พิจารณาใบสมัครให้ครบทั้งฟังก์ชันและสิทธิ์ เพื่อให้ฐานก่อนหน้าอัปเกรดได้ ไม่พึ่งเฉพาะ schema สำหรับฐานใหม่
- เพิ่มโหมดทดสอบ `npm --prefix database test -- --upgrade-from=8ddbf47` จำลอง schema ก่อนหน้าแล้วใช้ migration ใหม่ ผ่าน; ชุด SQL ปกติผ่าน และทดสอบ privacy บน Supabase จริงแบบ rollback ผ่าน
- แก้คลังแท็กให้ตัด Tab/ขึ้นบรรทัดใหม่ก่อนตรวจชื่อ ปิดช่องกรอกชื่อที่เป็นช่องว่างล้วน; regression test ล้มก่อนแก้และผ่านหลังแก้ทั้งในเครื่องและ Supabase จริง
- พบการบันทึกโปรไฟล์กับทักษะเป็นหลายคำขอ ซึ่งอาจบันทึกสำเร็จเพียงบางส่วน เปลี่ยนเป็น RPC transaction เดียวโดยใช้สิทธิ์ผู้เรียกและ RLS เดิม ทดสอบย้อนกลับเมื่อทักษะผิด/ปิดใช้งาน, เก็บประวัติทักษะเก่า, และห้ามผู้ว่าจ้าง/ผู้ไม่ล็อกอิน ผ่านทั้งในเครื่องและ Supabase จริง
- หลังแก้ lint, production build, ชุด SQL ฐานใหม่ และเส้นทางอัปเกรดจาก `main` ผ่าน; Security Advisor ยังมีคำเตือนเดิมเรื่องปิด leaked password protection ใน Auth

ยังต้องทดสอบ flow UI สองบัญชีบน Vercel และเช็ก Acceptance Criteria ด้วยตนเองก่อนปิด Sprint (โปรเจกต์นี้ทำคนเดียว)

## ปรับ UX/UI ของหน้าเว็บ

- ตรวจหน้าแรกและหน้าล็อกอินบนจอใหญ่/มือถือ แล้วแก้ข้อความหน้าแรกให้ตรงกับฟังก์ชันที่มีจริง
- ลดเมนูผู้ว่าจ้างจาก 7 รายการระดับบน เหลืองานหลัก 4 รายการกับกลุ่ม “คำขอ”; เพิ่มเมนูมือถือและซ่อนหน้าที่ยังไม่ได้ทำ
- ปรับหน้าหลักทั้งสามบทบาทให้บอกสิ่งที่ควรทำต่อ ช่วยให้เริ่มงานได้ทันที
- ปรับหน้าผู้ป่วย ประกาศ ค้นหางาน ใบสมัคร และคำเชิญให้สถานะว่าง/ตัวกรอง/ปุ่มไปต่อชัดขึ้น
- แยกสถานะด้วยป้ายข้อความและสี ปรับกรอบและระยะห่างให้หน้าอ่านง่ายขึ้น; รายละเอียดอยู่ใน [รีวิว UX/UI](../code-guide/11-frontend-ux-review.md)
- ตรวจตัวอย่างหน้าในเบราว์เซอร์ทั้งจอใหญ่และมือถือ รวมการเปิดเมนู/ตัวกรอง และตรวจไม่ให้ล้นแนวนอน; หน้าแรก ล็อกอิน และสมัครสมาชิกตรวจจากหน้าเว็บจริงในเครื่อง
- `npm run lint`, production build ด้วย Vite native config loader และ `git diff --check` ผ่าน; คำสั่ง `npm run build` ปกติติด `spawn EPERM` ขณะโหลด config บน Windows
- การยืนยัน flow จริงด้วยบัญชีทั้งสามบทบาทบน Vercel ยังเป็นงานถัดไป
- เก็บระยะหน้าผู้ว่าจ้าง 4 หน้าให้ใช้กรอบ 1160px และหัวข้อขนาดเดียวกัน; ตรวจในบัญชีผู้ว่าจ้างบน localhost ทั้งจอใหญ่และมือถือ 390px แล้ว ไม่พบเนื้อหาล้นแนวนอน
